# Responsible AI report

This is an empirical research instrument. It makes no claim of unbiased, hallucination-free or universally reliable behavior.

## Language representation and translation

The test manifest preserves Hindi and Tamil scripts and unanswerable examples. English uses a different benchmark population, so cross-language accuracy gaps cannot be interpreted as controlled parallel comparisons. Script routing is deterministic and conservative: transliteration, mixed scripts and short numeric questions require explicit language selection. Whitespace token F1 can miss semantic equivalence and is sensitive to morphology. Tokenizer round trips prove encoding fidelity, not understanding or answer quality.

The user-approved IndicSQuAD training supplement documents original split, licensing, preserved IDs, machine-translation status and ID mapping to original SQuAD training. Source language populations remain imbalanced. Actual training selected 256 usable base examples per language, with 25 English, 17 Hindi and 26 Tamil abstention additions, for 836 total examples. Validation used 32 examples per language. Exact text and preserved-ID checks cannot detect every semantic paraphrase, mistranslation or pretraining exposure. Validation-tuning choices and exposure risks belong in any resulting paper.

Campus machine translations remain unverified until their meaning is reviewed against the official source. AI review is explicitly labeled `machine_translation_ai_reviewed`, with human verification still pending; it is not recorded as human review. Only official-source-backed facts are eligible for this initial AI-curated pilot. The system cannot infer valid university policies from a generated answer alone. Human review remains necessary for independent semantic certification and for response factuality metrics.

## Grounding and evaluation

RAG only uses reviewed official snapshots with versions, freshness limits and optional effective dates. Evidence passages are treated as quoted untrusted data. Unrecognized citation labels and missing evidence cause abstention. The original guard required model-emitted labels and rejected all original campus C/D responses. The separately frozen follow-up permits attribution when the complete answer exactly matches a complete FAQ answer or evidence quote from one supplied source, retaining raw text and citation origin. This uses no reference answers or similarity matching. A copied passage may still be irrelevant or misleading; a valid citation is insufficient for factual support. Human claim reviews remain the grounding metric's basis. Reviewed factuality annotations are append-only and should include adjudication when reviewers disagree. The initial version stores reviewer attribution but does not estimate inter-rater agreement automatically.

Human factuality judgments use the original sealed reference corpus for all four campus configurations. A closed-book answer can be correct and supported by an official source even though that source was not supplied to the model. The review screen separates reference evidence from model-visible context and checks historical corpus versions and checksums. This avoids mechanically labeling every non-RAG response as hallucinated. Citation validity and model-context faithfulness remain distinct from factual correctness against authoritative sources.

Human factuality metrics remain pending until the eligible scope is fully reviewed. Failed predictions and missing annotations are visible. LLM-as-judge is not used as ground truth. Test questions are withheld from the dashboard's interactive dataset development browser. No validation/checkpoint choice uses test answers.

## Privacy and source stewardship

Only public university documents are in scope. Private portals, grades, credentials and student personal information are excluded. The default localhost application needs no cloud credentials or user tracking. Chat is not automatically inserted into research data. Human reviewers should avoid personal details in review notes. Source snapshots and redistributed benchmark records retain applicable attribution and content-license obligations.

Policy freshness requires actual recapture and review, not updating a timestamp automatically. Changes/deletions create new corpus/index versions; chat rejects mismatched current versions. Historical snapshots retained for reproducibility may need a retention decision if a source requests removal. The source registry and host allowlist must be deliberately updated for additional official services.

## Current limits

The original 7B model has not run on this laptop. The user explicitly authorized a 1.5B local experiment after the 7B memory audit; conclusions apply to that amended model and small training budget. Full paired benchmark evaluation, corrected local QLoRA training and both four-arm campus studies completed with zero failed predictions. An initial attempt with invalid augmentation was interrupted and excluded, with its history retained. Lexical benchmark F1 increased in all three populations, while the fresh campus comparison gives mixed LoRA-versus-base-RAG results. These outcomes establish neither human factual accuracy, reduced hallucination, language fairness nor a general advantage of LoRA + RAG. Original strict-citation results remain preserved; the 63-question and 45-question campus tests are distinct populations, so their percentages do not isolate the citation amendment's effect.

The current 57-FAQ corpus and test references are explicitly AI curated, with independent human source/translation certification pending and zero human response annotations. The follow-up has just six answerable source facts, two paraphrases per language, and relatively easy future/personal negative questions. Lexical/human confidence intervals resample responses rather than whole source articles; correlated questions can make them optimistic. Timing intervals resample whole generation batches. The positive-only retrieval threshold still needs richer negative validation before deployment claims. Source freshness is based on captured official publications rather than an on-site policy audit.

Timing observations come from a shared laptop desktop rather than an isolated performance host. A read-only sample during the LoRA benchmark recorded 98.6% system RAM use and about 0.33 GiB available (`results/studies/0f3dfb3d-298f-47c1-a020-4be01eb4bcec/runtime_health/20261108T042618Z.json`). Long-context latency therefore includes real host contention and must not be interpreted as a controlled measurement of adapter overhead alone. The owned dashboard preview was temporarily stopped to reduce memory pressure; model/generation settings were unchanged.

At 04:35:04 UTC, one Windows `EmptyWorkingSet` call targeted only the PID/creation-time/command-validated registered LoRA inference worker. Available host RAM immediately increased from 437 to 812 MiB; this is a page-residency observation, not a sustained memory or speed claim. Its complete record is `runtime_health/working-set-8a42a083-3748-46e4-a93e-dd05ac99ae24.json` under the study folder. Model weights/settings and saved outputs were not modified, and the intervention was not repeated periodically. All observed request durations, including any contention or page-fault stalls, remain in the metrics. See [Microsoft's API documentation](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-emptyworkingset).

A separate Ollama model was also using the GPU. Windows counters around 06:54 UTC reported approximately 2,319 MiB of dedicated GPU memory for it and 1,412 MiB for the benchmark worker. The other model was observed unloaded by 08:11 UTC; a subsequent sample showed 3,645 MiB dedicated GPU memory for the original benchmark worker and about 4.18 GiB host RAM available. These are point observations, not tensor-allocation peaks. Evidence is in `results/other_gpu_server_observation.json` and the study's `runtime_health/competing_model_unloaded_observation.json`.
