# Study amendments and protocol corrections

**Completion note (9 November local time):** the entries below preserve decisions as they were made. The original benchmark B later completed naturally, uninterrupted; no stop/recovery was executed. Both benchmark runs were replayed into v3 before campus evaluation, with lexical, abstention and timing dictionaries exactly unchanged. All ten evaluation runs and valid local training are now complete. Full results and IDs are in `FINAL_RESEARCH_REPORT.md`.

The original 63-question campus study exposed a missing-citation failure: both C/D arms abstained on every question. A separate conservative attribution extension was frozen before inference on a new 45-question, six-source test disjoint from the original corpus and validation sources. It preserves raw text and permits only complete verbatim source-answer/quote matches from one supplied document; it reads no gold references or aliases. The original outputs and metric snapshots remain unchanged. Embeddings, retrieval threshold, weights, prompts and generation stayed fixed. All four follow-up arms completed; outcomes are mixed and the two campus populations cannot estimate the citation change's causal effect. See [CITATION_POLICY_AMENDMENT.md](CITATION_POLICY_AMENDMENT.md) for the frozen protocol, audit and actual results. Human factuality metrics remain Pending.

On 7 November 2026 the user requested completing the actual experiment on the laptop GPU and explicitly authorized **Qwen/Qwen2.5-1.5B-Instruct** in place of the original 7B model. The active study is a **1.5B local GPU experiment**. Its results must not be presented as 7B results. The original 7B model/training configuration and inspection metadata remain archived under `config/profiles/` and `results/model_registry/`.

The original IndicQA/SQuAD held-out evaluation population is unchanged. The separately approved IndicSQuAD Hindi/Tamil training supplement remains in use. To bound laptop training time, the initial local study selects at most 256 usable base training examples per language and 32 validation examples per language after token-length filtering, with separately recorded training-only abstention augmentation. The prepared source corpus stays intact. These budgets are chosen before inspecting test predictions; every actual selected exposure count is recorded.

NF4/double quantization, FP16, rank 8, gradient checkpointing, batch 1 and accumulation 16 remain configured. The trainer computes the same masked answer-only causal cross-entropy while projecting only positions with supervised next-token labels, avoiding a full context-length by vocabulary logits tensor. Loss/gradient equivalence is tested. Validation loss still controls checkpoint selection; the test set never does.

All original test contexts are retained. An input-only token audit found a maximum prompt length of 8,438 tokens; the frozen input capacity is 9,216 tokens. On this Windows PyTorch build, native grouped-query SDPA selected a quadratic-memory fallback. Explicit KV-head expansion gives the mathematically equivalent attention operation and allows the available efficient SDPA kernel. Output and gradient equality, causal masking, padding masking and full-model behavior were checked. A real 9,216-token inference completed with peak CUDA tensor allocation of approximately 1.91 GiB; three training preflight steps peaked at approximately 2.32 GiB. These short probes do not guarantee dedicated-memory residency during a long run. The discarded preflight adapters are not research training checkpoints.

Benchmark inference groups records by language and input length only, in deterministic batches of at most four and a 4,096 padded-token budget; longer inputs run singly. Reference answers never determine batching. A/B use the same settings and population. A request's latency is its real batch-completion window, not batch duration divided by its size; throughput counts each shared generation duration only once. Campus inference runs singly. Generation is deterministic and capped at 192 new tokens, chosen before test outputs using the validation-only answer-length audit. Memory checks, protocol files and raw timing records are saved in `results/`.

The model's official checkpoint is pinned to `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`; the publisher declares Apache 2.0. Source: https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct . Actual memory, throughput, outputs, run IDs and outcomes will be reported after execution; authorization and preparation alone are not completed training.

Before the first completed metric snapshot, the reporting method was corrected to account for correlated timing measurements within generation batches. Version `qa-metrics-v2-batch-confidence` resamples whole batches for latency-mean and throughput confidence intervals. Point estimates, predictions, generation settings and timing measurements are unchanged. The already-running worker may first write its original v1 snapshot; saved predictions will then be replayed into an appended v2 snapshot before paired comparison. Human review also distinguishes authoritative reference evidence from model-supplied context for every campus arm and forbids marking answerable abstentions correct. These are scoring/reporting corrections, not changes to inference or checkpoint selection.

Abstention augmentation was corrected before releasing a valid adapter. Reusing the low-hash example-selection key for a 10% threshold overselected augmentation among the already selected examples. The coordinator had already started attempt `91da914a-8aef-4bab-a0cf-f2e4564d44cd` with 256 augmented examples per language; that attempt was interrupted after 26 observed optimizer steps and marked `protocol_valid: false`. Its logs and checkpoint are retained, and no adapter from it is eligible for the study. The full original-model baseline remains valid.

The corrected independent `empty-evidence-augmentation` hash implements the intended 0.1 probability. The configured fraction, source selection budget, training objective and validation-only checkpoint selection remain fixed; actual augmented counts are recorded separately by language. The initial preparation source snapshot is retained, with the corrected training source saved separately before the replacement run. The study resumes from its completed baseline without repeating model inference.

The upcoming campus pilot distinguishes official-source verification from human response evaluation. Explicit AI source/translation review can create `source_verified` records while retaining `human_review_status: pending`; it never creates `human_verified` records or human response annotations. Unreviewed translations remain excluded. Validation/test references disclose AI versus human curation, and every campus run records that policy. Human factual accuracy and hallucination metrics remain unscored without genuine human response reviews. This implements the brief's translation-review requirement without fabricating human reviewers; see `CORPUS_REVIEW_POLICY.md` for the initial pilot's limits.

GPU job teardown now retains the allocation lock through model cleanup, and evaluation publishes terminal status only after cleanup and lock release. Success/failure chat checks and all four isolated runner paths verify that ordering. This prevents a coordinator or chat request from allocating the next model while a preceding model is still unloading; it does not change prompts, generation, model weights or measured inference windows. The already-running benchmark worker was left uninterrupted.

Long-run Windows counters revealed shared GPU memory use that the initial allocated-peak probes did not capture. A bounded CUDA allocator policy and provenance-preserving recovery path were implemented and tested for subsequent jobs. Automatic review rejected changing the active job's terminal status while it could still write; that action was not executed. The user explicitly chose to keep the current benchmark uninterrupted, so the tested stop/recovery proposal was also not executed. The current A/B model, prompt, generation, batching and original worker remain unchanged. Future runs snapshot their bounded memory policy separately from model settings, and comparisons disclose policy differences when present. See `MEMORY_RECOVERY_PLAN.md` and `results/memory-recovery-validation.log`.
